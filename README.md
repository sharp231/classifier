# End-to-End Image Classification App (CIFAR-10)

画像認識モデルの学習から Web アプリケーションとしてのデプロイまでを、End-to-End で実装したプロジェクトです。  
ユーザーがアップロードした画像を AI が解析し、CIFAR-10 の 10 クラスに分類します。

## プロジェクト概要

機械学習モデルを作成するだけでなく、実際の Web サービスとして動作させるための設計、実装、デプロイまでを行いました。
入力画像の向きや縦横比の違いを吸収する前処理、推論結果を安定させる Test Time Augmentation、pytest と GitHub Actions による自動テストを取り入れています

- **担当領域:** 企画・要件定義 / モデル構築 / Web 実装 / テスト / デプロイ

## 技術的工夫 (Key Features)

### 1. 推論精度の安定化 (Test Time Augmentation)

単一の推論結果だけに依存せず、入力画像を複数の倍率（1.0, 0.8, 0.65）でクロップして推論し、その平均値を最終結果として採用しています。
これにより、被写体の位置や大きさの違いによる判定のぶれを抑え、より安定した分類結果を返せるようにしています。

### 2. 堅牢な前処理パイプライン

ユーザーがアップロードする画像は、撮影端末や保存形式によって向きや縦横比が異なるため、推論前に以下の前処理を行っています。

- **EXIF 自動補正:** スマートフォン写真などに含まれる回転情報を反映し、正しい向きに補正
- **Center Crop:** アスペクト比を維持したまま中央を切り抜き、単純なリサイズによる画像の歪みを防止
- **RGB 変換:** 推論モデルに入力できる形式へ統一

### 3.ロギングと運用時の可観測性

本番運用時のトラブルシューティングを行いやすくするため、print ではなく Python 標準の logging モジュールを使用しています。
ログにはタイムスタンプ、ログレベル、メッセージを含め、アップロード処理、モデル読み込み、エラー発生箇所を追跡しやすい構成にしています。
これにより、Render などの本番環境でも、エラーの発生タイミングや原因を確認しやすくしています。

### 4. 安定性を重視したアーキテクチャ

モデルの読み込みや画像アップロード処理では、アプリ全体が不安定にならないように以下を意識しています。

- **Lazy Loading:** 必要になったタイミングでモデルを読み込み、起動時の負荷を軽減
- **多層入力検証:** ファイルサイズ、拡張子、申告MIMEタイプ、Pillowによる実画像形式を照合
- **画像内容検証:** 破損画像、空ファイル、過大な縦横サイズ・総ピクセル数を拒否
- **安全な保存名:** 元のファイル名を使用せず、UUIDを使ったファイル名で保存
- **保存順序:** すべての検証に成功した画像だけを保存 
- **クリーンアップ:** 保存処理または推論処理の失敗時に、作成途中のファイルを削除
- **安全なエラー応答:** 独自例外によってユーザー向けメッセージとHTTPステータスを統一 

## Testing / CI

本プロジェクトでは、`pytest` と GitHub Actions を用いて、画像認識アプリの主要な Web フローを自動テストしています。

### テスト対象

現在のテストでは、以下を確認しています。

- トップページと画像判定フロー
- ファイル未選択と不正な拡張子の拒否
- ファイルサイズの上限
- PNG・JPEG画像の正常受付
- 拡張子・MIMEタイプ・実画像形式の一致
- 空ファイル、破損画像、過大画像の拒否
- 検証前に不正画像が保存されないこと
- UUID形式の安全なファイル名で保存されること
- 保存失敗時に作成途中のファイルが削除されること
- 推論失敗時に保存済み画像が削除されること

正常系のテストでは、本物の `image_classifier.h5` を読み込まず、`DummyModel` によって推論処理をモックしています。  
Webフローのテストでは `DummyModel` を使用し、本物のモデルファイルに依存せず安定して検証しています。

### テスト実行

```bash
uv run pytest
```

## Renderへのデプロイ

Render Web Serviceでは、以下の設定を使用します。

| 項目 | 設定値 |
| :-- | :-- |
| Runtime | Python 3 |
| Build Command | `uv sync --frozen --no-dev` |
| Start Command | `uv run gunicorn app:app --bind 0.0.0.0:$PORT --log-file -` |
| Environment Variable | `PYTHON_VERSION=3.13.5` |

`uv.lock` をリポジトリ直下へ配置することで、でも固定された依存関係を使用します。

### アップロード画像の保存

アップロード画像は `data/uploads` に一時保存されます。
Render Freeのローカルファイルシステムは永続化されないため、再デプロイ、再起動、スピンダウン時に画像は削除されます。現在の画像判定用途では一時保存として扱い、永続的なデータ収集には使用しません。
将来、誤分類画像の収集やMLOpsへ利用する場合は、外部オブジェクトストレージの導入を検討します。

ブラウザで `http://127.0.0.1:5000` にアクセスしてください。
